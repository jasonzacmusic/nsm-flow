01 · Mission rules

Test fearlessly. Handle data carefully.

This is an alpha build. A successful test is not “it opened once.” A successful test tells us exactly what works, what fails, how often, and on which machine.

Use fake information

Never dictate real student details, payment data, passwords, health information, private emails, or confidential NSM messages.

Do not send anything

Test inside drafts or blank documents. Do not press Send in Gmail, WhatsApp, Outlook, ChatGPT, or any production system.

Capture evidence

For every failure, keep the exact spoken sentence, actual output, expected output, screen recording or screenshot, and repetition count.

“100% working” is a release target, not an assumption. If a test passes once, repeat it. If it fails once, try to reproduce it three times and report the result—even if restarting the app fixes it.

  1. Open the supplied DMG and drag NSM Flow to Applications.

  3. Allow Microphone and Accessibility when macOS asks.
  4. Complete onboarding and download the recommended local model.
  5. Confirm the default push-to-talk shortcut shown in NSM Flow is Fn.

Windows

  1. Open the supplied NSM Flow setup file.
  2. If SmartScreen appears, continue only when the installer name and source match the coordinator's message.
  3. Allow microphone access when Windows asks.
  4. Complete onboarding and download the recommended local model.
  5. Confirm the default push-to-talk shortcut shown in NSM Flow is Ctrl+Space.

Installation checklist

  • The installer completes without freezing or unexplained errors.
  • The app opens from Applications or the Start menu.
  • The NSM Flow name and icon appear correctly.
  • Onboarding text fits the screen and every button works.
  • Microphone and Accessibility instructions are understandable.
  • A local speech model downloads and becomes selectable.
  • The app can quit and reopen without repeating onboarding.
  • Settings remain after restart.

07 · Break the edges

Stress, privacy, recovery, and polish.

Shortcut and recording

  • Tap shortcut too briefly
  • Hold for 5, 30, 60, and 180 seconds
  • Release while still speaking
  • Press Escape to cancel
  • Press the shortcut repeatedly and rapidly
  • Switch apps while recording
  • Lock and unlock the computer
  • Sleep and wake the computer

Audio and devices

  • Disconnect microphone mid-recording
  • Connect Bluetooth headphones after launch
  • Mute microphone at system level
  • Test silence and background speech
  • Test clipping from a voice too close to the mic
  • Change input device in settings
  • Verify no endless recording state remains

Privacy and offline

  • Disconnect internet and complete local dictation
  • Confirm failures explain what needs internet
  • Check audio retention remains Delete immediately
  • Inspect history; deleted items stay deleted
  • Ensure transcript text never appears in normal logs
  • Confirm local dictation works without any employee login
  • If optional Google sign-in is visible, cancelling it must recover cleanly and never expose a token

Visual and accessibility

  • Light and dark mode
  • Small laptop screen and large monitor
  • 125%, 150%, and 200% display scaling
  • Keyboard-only navigation
  • Screen reader labels where available
  • Long model, microphone, and account names
  • No clipped text, overlap, or invisible controls
Stop and report immediately if NSM Flow sends a message without permission, pastes into the wrong app, exposes private text or credentials, deletes unrelated data, continually records after release, or causes repeated crashes.
08 · Bug reporting

One clear report can save hours.

Search existing issues first. If you have access to the private NSM Flow GitHub repository, use the “Intern QA bug” issue form. Otherwise, send the completed template below to your assigned NSM Flow coordinator. One report must describe one bug.

S0 Stop testing

Data exposure, unintended send/submit, data loss, uncontrolled recording, or system-level damage.

S1 Critical

App will not install/open, repeat crash, no dictation, or output consistently enters the wrong app.

S2 Major

Wrong transcription or musical meaning, broken formatting, unreliable shortcut, significant lag, or failed permission flow.

S3 Minor

Visual polish, wording, alignment, small usability issue, or rare failure with a practical workaround.

  • Every failure was retried at least three times.
